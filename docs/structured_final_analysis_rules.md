# Final analysis and default model

These details are recorded before the larger experiments or their test scores.
They specify delivery of the winning architecture already required by the
campaign protocol; they do not change the training recipes.

Finish all six larger models. Compare the two four-million-row architecture
pairs using only their final **development** STS-B Spearman. Apply the same
development teacher/rank viability thresholds to the structured pair as in the
screen. The one-million-row matched-exposure pair remains a scientific control;
the default release comes from a four-million-row pair.

Use the screen's measured reference repeat and the two larger pairs' seed
spreads as the conservative deployment tie preference. Prefer fewer enabled
additions, fewer parameters, then lower step time inside that band, preserving
the raw mean leader in the report. The screen repeat is **not a measured
four-million-row repeat**. This delivery rule does not turn two final seeds
into a population-level significance claim or certify a full-stage hardware
noise floor.

If the relative control is the stronger development choice, it may become the
default; the complete structured pair stays available. An unsuccessful
transfer must not be relabeled as a successful one to determine the release.
Within the chosen pair, deploy the seed with the better development score,
breaking an exact tie toward seed1. Report both members.

After making that development-only decision, present all six models' held-out
chunk060 and eight-task test results. Do not choose the default architecture,
seed or reported benchmark tasks using those tests. Keep word-record lookup,
teacher reproduction, sentence similarity and inference parity as separate
measurements.

Frozen binding-off, norm-off and phase-redraw measurements are interventions
on trained checkpoints. Any change is a dependency of that trained model,
not evidence that a newly trained recipe would improve. Per-query lookup
averages and equally weighted per-caption averages are reported separately.
The sampled captions, rather than their repeated query positions, are the
independent input units. Long synthetic shapes establish execution and output
shape only; training remained limited to256 tokens.

The bounded exploratory follow-up also checks two structural dependencies:
set only the hierarchical anchor-angle frequencies to zero, and replace each
level's learned value-address rows with that level's digit-zero row. The latter
preserves its default learned offset while removing address variation. Restore
all tensors exactly after each intervention. Run these on the selected
structured larger checkpoints; run the original binding/norm/phase checks on
the complete KALLP screen pair even if that package is not promoted. Report
development effects without treating a frozen intervention as an improved
training recipe. This adds no new accuracy training.

After the intact KALLP head reached perfect sampled top-one lookup, add a
reconstructed zero-step control for its two registered seeds. This separates
the architectural prior from changes due to training. Rebuild it in the same
frozen runtime; do not describe it as an independently saved original birth
checkpoint. This is a post-screen mechanism control and changes no selection
rule or training recipe. Preserve the original intact measurements and write
the follow-up, its software environment and TensorBoard endpoint scalars to a
separate versioned folder.
